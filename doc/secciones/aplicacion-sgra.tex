\section{Aplicación al SGRA}
Del caso de LinkedIn tomaría la idea de usar eventos para separar el envío de
avisos de la operación que los origina. En el SGRA, una vez guardado el nuevo
horario, se publicaría el evento \texttt{TutoriaReprogramada} para que el módulo
de notificaciones avise a los participantes. Si el envío falla, podría
reintentarse sin repetir la reprogramación. Para evitar avisos duplicados,
el módulo registraría qué destinatarios ya recibieron el aviso de ese evento.
No incorporaría Apache Kafka ni Apache Beam, porque el volumen previsto de
tutorías permite resolver este flujo con un mecanismo de publicación y consumo
más sencillo de mantener.

\paragraph{Ejemplo de primera mano.}
En el tablero de GitHub Projects que usé con mi equipo, al cerrarse un
\textit{issue}, su tarjeta pasaba automáticamente a \textit{Done}.
El cierre del \textit{issue} era el evento que activaba ese cambio.
